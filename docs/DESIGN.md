## 设计理念

以个人身份和长期研究方向建立首页，而不是先展示文章列表。暖白纸面、墨色文字、松绿色强调，以及暗色模式下的深青灰底色构成统一视觉。星图由轻量 SVG 绘制，将 Database、Systems、AI 与 Algorithms 的关联转化为个人标识；没有粒子系统、玻璃背景或自动播放装饰。

正文使用本地中文字体回退，避免远程字体依赖；正文宽度 760px、约 1.95 倍行距。英文字段与序号使用等宽字体辅助索引。浅色与暗色通过同一套语义变量维护。动画只用于反馈，并尊重 reduced-motion。

首页依次为：身份 → 当前方向 → 项目 → 近期文章 → 六领域知识地图 → 系列专题。

## 实现

- 可复用的 SectionHeading、ProjectCard、OrbitMap、KnowledgeMap。
- 三个项目的独立详情页。DBMS_C 的内容来自本地 README、模块关系说明和原图，远端名称为 PhoenixDB。AI-NATIVE-DBMS-C 的内容区分当前 Core Containers 阶段与后续 DBMS / AI 规划。Aster 按作者说明标为筹备中。
- 知识地图按实际内容计数；没有笔记的方向展示学习路径，不伪造内容。
- Series 使用独立专题卡片，沿用项目卡片的边框、圆角、间距和 hover。统一配置决定标题、描述与阅读顺序，已发布文章自动决定数量与更新时间。
- 主题跟随系统并持久化手动选择；无闪烁初始化、导航当前状态、跳至正文、键盘焦点、减少动画偏好。
- 中文阅读样式、Shiki 双主题、MathJax、目录高亮、进度条、代码复制、大图对话框与 Escape 关闭。
- canonical、描述、社交分享图、JSON-LD、RSS、sitemap；搜索和 404 设置 noindex，sitemap 排除两者。

## 验证

- `npm test`：6 个测试通过，覆盖查找存在/不存在、排序边界与重复值、LRU 命中淘汰、B+Tree 分隔键、BFS 距离、增长模型边界。
- `npm run build`：生成 25 个页面与 3 篇可索引内容的 Pagefind 索引。
- `node scripts/verify-build.mjs`：检查 HTML 元数据、站内链接与资源、分享图尺寸、sitemap 与草稿隔离。
- Playwright / Edge：18 个页面 × 360 / 768 / 1440 像素；交互和截图保存在同级 `design-qa-20260922`。
- 开发预览单独检查板凳龙草稿的手机公式、暗色与 reduced-motion；不改变发布状态。
- 本机受限沙箱曾产生依赖加载与 spawn EPERM，生产构建和浏览器验收在正常权限下执行；未为此留下依赖绕过配置。
- 独立类型检查现通过 `npm run check` 执行；当前 Series 验证结果见 [维护指南](SERIES.md)。

## 后续建议

1. 优先把现有 Buffer Pool 结构测试补成完整笔记，并与数据库开发系列互相引用。
2. 审阅板凳龙草稿的来源与公式后，由作者决定何时发布；把站点测试文章设为草稿也是后续内容整理事项。
3. 增补数据库的实际运行截图、性能数据和阶段日志，引用对应提交；这些材料比增加装饰更能形成个人辨识度。
4. Aster 明确方向后，在集中项目数据中补充真实资料；可为更长项目档案引入独立 Markdown collection，无需改变现有框架。
5. B+Tree 后续可增加插入分裂、删除合并；图算法可扩展 Dijkstra；保持纯状态转换和有界输入。
6. 准备发布时再提交并触发现有 GitHub Pages 工作流；建议在实体手机与其他浏览器复查。
